1. ONE-SENTENCE SCOPE
---------------------
Mortis is an AI trading agent that analyzes BTC across multiple timeframes,
paper-trades with deterministic risk controls, and stores decision and trade
events in a local SQLite database with a verifiable SHA-256 hash chain.

Pitch line: "The AI decides, code limits the risk, and the blockchain proves
what the AI decided and when."

Anything that does not serve that sentence is out of scope.

3. HONEST CONSTRAINTS (do not violate in code or in docs)
---------------------------------------------------------
  - Paper trading ONLY. No real funds or exchange orders. Not financial advice.
  - Leverage is simulated only, configurable from 1x to 10x. Each position is
    isolated to its reserved margin; its loss is capped at that margin.
  - Charge a 3% fee once per completed round-trip, calculated on entry notional.
  - Persist trades in SQLite and append each trade event to the local hash chain.
    This is not a public blockchain and does not provide external immutability.
  - Do NOT claim the system is profitable. Report honest backtest numbers
    (win rate, max drawdown, vs buy-and-hold).
  - The strategy uses public Binance market data in a paper-trading engine.
  - A local hash chain can detect edits when verified, but is not publicly
    anchored and does not prove that the reasoning was correct.
  - LLM "confidence" numbers are not calibrated probabilities. Log them and
    measure calibration later; never treat 0.99 as a reason to bet bigger.
  - Latency target is seconds/minutes, NOT microseconds. LLM agents do not do HFT.
  - The autonomous paper trader starts with the local engine and evaluates a
    strategy every 15 minutes; plain-code position checks run every 5 seconds.
  - Leverage never exceeds 10x; AI leverage defaults to the configured 1x.
  - The LLM never does arithmetic that matters (indicators, SL/TP, sizing).
    Those are deterministic code.


4. ARCHITECTURE
---------------
Two paths:

  SLOW PATH (every 15 min, LLM agents):
    fetch data -> TA agent + News agent -> Lead agent consensus ->
    deterministic risk/sizing -> build decision JSON -> canonicalize + hash ->
    store JSON locally -> open the simulated paper trade -> append trade event
    and result to SQLite's SHA-256 hash-chained ledger.

  FAST PATH (plain code, every 5 seconds):
    watch price feed -> check open paper position against SL/TP -> close it.
    No LLM involved.

Components:

  [TA Agent]       reads indicator values computed by code (not by the LLM),
                   returns direction + confidence + short rationale.
  [News Agent]     reads recent headlines, returns sentiment direction +
                   confidence + short rationale.
  [Whale Agent]    STRETCH ONLY. Not in MVP.
  [Lead Agent]     weights agent outputs, applies threshold, may veto.
                   Does NOT compute prices or sizes itself.
  [Risk Engine]    pure Python: ATR-based SL/TP, sizing, caps, kill switch.
  [Paper Engine]   pure Python: SQLite-backed simulated account, margin,
                   positions, PnL, fees, and isolated-margin liquidation.
  [Chain Layer]    local SHA-256 transaction event chain and verifier.
                   Public blockchain writes are a separate future feature.
  [Dashboard]      Streamlit: decisions, equity curve vs buy-and-hold,
                   tx links, Verify button.


5. AGENT CONTRACTS (strict, validate with Pydantic)
---------------------------------------------------
Every sub-agent returns exactly:

  {
    "agent": "ta" | "news" | "whale",
    "direction": -1 | 0 | 1,          # -1 short/bearish, 0 neutral, 1 long/bullish
    "confidence": 0.0 - 1.0,          # clamp at 0.95; >0.95 is flagged suspicious
    "rationale": "max 3 sentences",
    "inputs_digest": "short summary or hash of the data the agent saw"
  }

Reject and retry (max 2 retries) on invalid output. On failure, treat the agent
as direction 0, confidence 0 and log the failure.

Timeframes for TA:
  4h  -> trend direction
  1h  -> setup / structure
  15m -> entry timing
Indicators (computed in code): RSI(14), MACD(12,26,9), EMA(20/50/200),
ATR(14), simple support/resistance from recent swing highs/lows.
Windows note: TA-Lib can be painful to install. Use recent TA-Lib wheels if
available, otherwise fall back to pandas-ta or the "ta" library. Keep the
indicator functions behind one interface so the library can be swapped.


6. CONSENSUS, THRESHOLD, SIZING (deterministic)
-----------------------------------------------
Config (in config.yaml, all tunable, all logged in each decision):

  weights:            ta=0.6, news=0.4          (tune via backtest)
  threshold:          0.60
  min_agreeing:       2                          (when >=2 agents active)
  confidence_cap:     0.95
  base_risk_pct:      0.0075   (0.75% of equity risked per trade)
  max_size_multiplier:1.5
  max_notional_pct:   0.50     (base notional cap, multiplied by leverage)
  max_leverage:       10
  max_open_positions: 1
  max_daily_loss_pct: 0.03     (hard stop for the day -> kill switch)
  sl_atr_mult:        1.5
  tp_atr_mult:        2.5
  fee_pct_round_trip: 0.03     (charged once on close against entry notional)
  slippage_pct:       0.0005
  leverage:           1        (AI default; 1x-10x paper simulation)

Score:
  score = sum(w_i * direction_i * min(conf_i, cap)) / sum(w_i)    # range -1..1

Trade only if |score| >= threshold AND at least min_agreeing agents agree on
the sign. Otherwise decision = "no_trade" (this is the most common and
correct outcome; still log it and hash it).

Entry / SL / TP:
  entry = current price (paper fill + slippage)
  long : SL = entry - sl_atr_mult*ATR ; TP = entry + tp_atr_mult*ATR
  short: SL = entry + sl_atr_mult*ATR ; TP = entry - tp_atr_mult*ATR

Sizing:
  risk_budget = equity * base_risk_pct * size_multiplier
  size_multiplier = clamp(1 + 0.5*(|score|-threshold)/(1-threshold), 1.0, max_size_multiplier)
  risk_per_btc = |entry - SL| + entry * fee_pct_round_trip
  position_size = risk_budget / risk_per_btc
  then cap so notional <= max_notional_pct * equity * leverage
  Report actual risk as position_size * risk_per_btc. Do not open an AI trade
  unless its expected take-profit distance is greater than the round-trip fee
  per BTC; a nominal target below fees is expected to lose after costs.

Trailing logic (checked on each 15-min loop):
  If TP is hit and a fresh Lead decision still agrees with the direction,
  raise TP by 1 ATR and move SL to the prior TP or break-even (pick one, log it).
  Otherwise close at TP.
  If SL and TP are both touched inside one candle, assume SL hit first
  (conservative).

The LLM may suggest a size multiplier, but code clamps it. The LLM can never
raise limits, only stay within them.


7. DECISION RECORD (the "Proof of Reasoning" JSON)
--------------------------------------------------
One record per 15-min cycle, including "no_trade" cycles.

  {
    "schema_version": "1.0",
    "decision_id": "uuid",
    "timestamp_utc": "ISO-8601",
    "symbol": "BTCUSDT",
    "model": "gemini model id used",
    "prompt_hashes": {"ta": "...", "news": "...", "lead": "..."},
    "config_snapshot": { ...the config values in section 6... },
    "inputs": {
      "price": 0.0,
      "candles_digest": "sha256 of the candle data used",
      "headlines_digest": "sha256 of headlines used"
    },
    "agent_outputs": [ ...section 5 outputs... ],
    "score": 0.0,
    "action": "long" | "short" | "no_trade",
    "trade": {
      "entry": 0.0, "stop_loss": 0.0, "take_profit": 0.0,
      "size": 0.0, "risk_amount": 0.0, "leverage": 1
    },
    "risk_checks": {"daily_loss_ok": true, "open_positions_ok": true, "notional_cap_ok": true},
    "previous_decision_hash": "hex or null"
  }

Hashing:
  - Canonicalize: JSON with sorted keys, no extra whitespace, UTF-8.
  - hash = keccak256(canonical_bytes)  (or sha256; pick one and document it)
  - Chain decision records via previous_decision_hash.
  - Store full JSON in /decisions/<decision_id>.json.
  - Trade open/close events are separately persisted in SQLite and hash-chained.
  - The local hash chain detects edits; it is not a public blockchain.

Outcome records (trade closed, PnL) are written separately, linked by
decision_id, and optionally also hashed on-chain.

10. TECH STACK
--------------
  Language: Python 3.11+ (developer machine is Windows; keep paths and
            commands Windows-friendly, use pathlib)
  Agents:   google-adk + Gemini API
  Data:     Binance public REST/WebSocket (python-binance or plain requests),
            feedparser for RSS, Tavily for search, NewsAPI optional
            (free tier is limited; do not depend on it alone)
  Indicators: TA-Lib or pandas-ta / ta (see section 5 note)
  Validation: pydantic
  Web3:     coinbase-agentkit (Python), web3.py, Solidity + Foundry or Hardhat
            (or Remix for a fast deploy)
  UI:       Existing Next.js dashboard (npm run dev, port 3001)
  Storage:  SQLite via Python stdlib; local paper account in data/mortis.db
  Whale data (stretch only): mempool.space or Blockstream API for BTC.
            Etherscan is Ethereum-only and not suitable for BTC.
            CryptoQuant is paid. Twitter/X RSS is not viable.

13. EXPERIMENT LOG TEMPLATE (EXPERIMENTS.md)
--------------------------------------------
For each experiment:
  - Date
  - Question (e.g. "Does threshold 0.7 beat 0.5?")
  - What changed
  - Result (numbers: return, win rate, drawdown, #trades)
  - Decision (keep / revert) and why
Suggested experiments:
  - threshold 0.5 / 0.6 / 0.7 / 0.8
  - TA only vs TA+News
  - weights 0.6/0.4 vs 0.5/0.5 vs 0.7/0.3
  - SL/TP ATR multiples
  - single timeframe vs multi-timeframe
  - with vs without trailing TP
  - confidence calibration: do 0.7-0.8 calls actually win more than 0.5-0.6 calls?
  - Gemini model variants (speed vs quality)

15. RULES FOR THE AI CODING ASSISTANT
-------------------------------------
  - Follow the project structure in section 9.
  - Keep functions small and typed; add docstrings; write tests for
    indicators, risk, hashing, and the paper trader.
  - Never hardcode secrets. Read from .env.
  - Never let the LLM compute prices, indicators, stop-loss, take-profit, or size.
  - Validate every LLM output with Pydantic; retry on failure; log failures.
  - Every config value used in a decision must be copied into that decision.
  - Never add real-money exchange execution or mainnet support.
  - Paper leverage is capped at 10x; fees are 3% once per completed trade.
  - Do not claim the Gemini model is trained or profitable. Store outcomes for
    later evaluation; change strategy parameters only through measured tests.
  - Do not add features outside this file without asking.
  - When a library API is uncertain, check the official docs and say so
    instead of guessing.
  - Commit small and often.
