2. WHAT THE WEEK 1 AGENT DOES (target behavior)
-----------------------------------------------
User chats with the agent, e.g.:
  "Analyze BTC across timeframes and decide if there is a trade."
The agent:
  1. calls get_market_snapshot -> real BTC data + indicators for 4h / 1h / 15m
  2. reasons about trend (4h), setup (1h), entry timing (15m)
  3. calls submit_trade_decision with direction, confidence, short rationale
  4. CODE (not the LLM) checks the confidence threshold, computes entry,
     ATR-based stop-loss and take-profit, position size, applies risk caps,
     and opens a simulated (paper) position - or logs "no_trade"
  5. replies with a clear summary of what it decided and why
User can also ask: "Show my paper account" / "Check my open position".
Existing starter behaviors (wallet info, paid weather API via x402, dice) must
KEEP WORKING - do not delete starter tools. The wallet will be used in Week 3.

4. CONFIG (create agent/config.ts, single source of truth)
----------------------------------------------------------
  export const CONFIG = {
    symbol: "BTCUSDT",
    timeframes: ["4h", "1h", "15m"],
    candlesPerTimeframe: 300,        // needed for EMA200
    confidenceThreshold: 0.60,       // below this -> no_trade
    confidenceCap: 0.95,             // clamp; values above are suspicious
    startingEquityUsd: 10000,        // paper account
    baseRiskPct: 0.0075,             // 0.75% of equity risked per trade
    maxSizeMultiplier: 1.5,
    maxNotionalPct: 0.50,            // NOTE: PRD had 0.25, see note below
    maxOpenPositions: 1,
    maxDailyLossPct: 0.03,           // block new trades after -3% on the UTC day
    slAtrMult: 1.5,
    tpAtrMult: 2.5,
    atrTimeframe: "1h",
    feePctPerSide: 0.001,            // 0.1%
    slippagePct: 0.0005,             // 0.05%, applied to entries and stop exits
    leverage: 1,                     // never change in Week 1
    promptVersion: "v1",
  };
  NOTE on maxNotionalPct: with a 1.5x ATR stop the stop distance is usually
  ~1% of price, so risking 0.75% of equity needs ~75% notional. A 25% cap would
  almost always override the risk rule. Cap raised to 50% (still 1x leverage,
  no borrowing). Log "capped_by_notional" in each decision. This is an
  experiment candidate for EXPERIMENTS.md.


5. MUST-HAVE BUILD LIST (in this order)
---------------------------------------

5.1 Market data module  (agent/market.ts)
  - Fetch klines for BTCUSDT for 4h, 1h, 15m (limit 300).
  - Base URLs to try in order (fallback on network/451/403 errors):
      https://data-api.binance.vision
      https://api.binance.com
    Endpoint: /api/v3/klines?symbol=BTCUSDT&interval=15m&limit=300
    Latest price: /api/v3/ticker/price?symbol=BTCUSDT
    (Public endpoints, no API key. If Binance is blocked in the user's region,
    switch to another public source and keep the same internal candle type.)
  - Parse into { openTime, open, high, low, close, volume, closeTime } numbers.
  - DROP the still-forming candle (closeTime > now) so indicators only use
    CLOSED candles (no lookahead / no repainting).
  - Handle errors with clear messages (the LLM must be told when data failed
    and must NOT invent numbers).

5.2 Indicators module  (agent/indicators.ts)  - deterministic, no LLM
  - Prefer the npm package "technicalindicators" (pure JS, installs fine on
    Windows). If it causes install/type problems, hand-write EMA, RSI(Wilder),
    ATR(Wilder), MACD - they are short.
  - Per timeframe compute from closed candles:
      lastClose, EMA20, EMA50, EMA200,
      RSI14,
      MACD(12,26,9): macd, signal, histogram, histogramRising (bool),
      ATR14 (absolute) and atrPct (ATR / close),
      volumeRatio (last volume / average of previous 20),
      swing support/resistance: nearest recent swing low below price and swing
        high above price (pivot with 3 bars each side over the last ~100 bars),
      trendFlags: priceAboveEma50, ema20AboveEma50, ema50AboveEma200
  - Round to sensible decimals. Keep the output SMALL (the LLM token budget and
    free-tier rate limits matter). No raw candle arrays in tool output.
  - Quick sanity check: compare RSI/EMA on one timeframe with TradingView or
    Binance chart values; small differences are OK, big ones mean a bug.

5.3 Tool: get_market_snapshot  (add to agent/tools.ts)
  - No parameters. Returns: { asOf, price, timeframes: { "4h": {...}, "1h":
    {...}, "15m": {...} }, candlesDigest }.  candlesDigest = sha256 of the
    closed-candle data used (for the decision log).
  - description (be specific so Gemini uses it): "Get live BTC/USDT price and
    multi-timeframe technical indicators (4h trend, 1h setup, 15m entry). Always
    call this before making any trading decision."

5.4 Risk module  (agent/risk.ts) - pure functions, unit-testable
  Inputs: direction (long|short), confidence, price, atr (from 1h), equity.
  Rules:
    - if confidence > confidenceCap -> clamp to cap, flag "confidence_clamped"
    - if direction is neutral OR confidence < confidenceThreshold -> no_trade
    - entry (long)  = price * (1 + slippagePct) ; short = price * (1 - slippagePct)
    - slDistance = slAtrMult * ATR ; tpDistance = tpAtrMult * ATR
      long : SL = entry - slDistance ; TP = entry + tpDistance
      short: SL = entry + slDistance ; TP = entry - tpDistance
    - sizeMultiplier = clamp(1 + 0.5*(conf - threshold)/(1 - threshold),
                             1.0, maxSizeMultiplier)
    - riskAmount = equity * baseRiskPct * sizeMultiplier
    - size (BTC) = riskAmount / slDistance
    - if size*entry > equity*maxNotionalPct -> size = equity*maxNotionalPct/entry
      and flag "capped_by_notional"
    - leverage fixed at 1
  Hand-check test case (put in scripts/sanity.ts, run with `npx tsx`):
    equity 10000, price 60000 (ignore slippage for this check), ATR 400,
    long, confidence 0.60:
      slDistance = 600 ; tpDistance = 1000 ; SL 59400 ; TP 61000
      multiplier 1.0 ; riskAmount 75 ; raw size 0.125 BTC (notional 7500)
      notional cap 5000 -> size 0.083333 BTC, capped_by_notional = true,
      actual risk = 0.083333 * 600 = $50.

5.5 Paper trading engine  (agent/paper.ts)
  - State: { equity, startingEquity, openPosition | null, closedTrades[],
    realizedPnlByDay }.  Persist as JSON in data/paper-account.json
    (create folder if missing). On Vercel the filesystem is read-only except
    /tmp, so use os.tmpdir() when process.env.VERCEL is set (state is then
    ephemeral - acceptable for Week 1; mention it in the README).
  - openPosition: { id, side, entry, size, stopLoss, takeProfit, openedAt,
    decisionId, feesPaidOpen }.
  - Open: charge fee = notional * feePctPerSide at entry.
  - Settlement (run whenever the account is read, and before any new trade):
    fetch 15m candles since openedAt; walk them in order;
      long : if low <= SL -> exit at SL (apply slippage against us) ;
             else if high >= TP -> exit at TP (no slippage, limit fill)
      short: mirrored.
    If SL and TP are both touched inside the same candle assume SL hit first
    (conservative). Charge exit fee. Record closed trade with PnL in USD and
    in R-multiples (pnl / initial riskAmount), exit reason (SL | TP).
  - Unrealized PnL for an open position using the latest price.
  - Guards (enforced in code, return a clear refusal to the agent):
      * maxOpenPositions = 1
      * daily loss limit: if realized PnL today (UTC) <= -maxDailyLossPct of
        the day's starting equity -> block new trades
      * paper only: no code path may touch real funds or mainnet

5.6 Decision log  (agent/decisionLog.ts)
  - EVERY call of submit_trade_decision (including no_trade) writes
    data/decisions/<decisionId>.json with:
      schemaVersion "1.0", decisionId (uuid), timestampUtc, symbol, model,
      promptVersion, config snapshot, inputs { price, candlesDigest },
      agentOutput { direction, confidence (raw and clamped), rationale },
      action (long | short | no_trade), reasonIfNoTrade,
      trade { entry, stopLoss, takeProfit, size, riskAmount, flags[] } | null,
      riskChecks { threshold_ok, open_positions_ok, daily_loss_ok,
      notional_cap_ok }, previousDecisionHash
  - hashDecision(record): canonical JSON (keys sorted, no whitespace, UTF-8)
    -> sha256 hex via node:crypto. Keep this in ONE function so it can be
    swapped for keccak256 in Week 3. Store the hash in the record's sidecar
    (e.g. <decisionId>.hash) or an index file, and chain it through
    previousDecisionHash. (Local only in Week 1. On-chain posting is Week 3.)

5.7 Tool: submit_trade_decision
  - Parameters: direction ("long" | "short" | "neutral"), confidence (number
    0..1), rationale (string, max ~3 sentences).
  - IMPORTANT: the LLM supplies ONLY these three values. The tool re-fetches
    fresh data, and CODE computes entry, SL, TP, size via risk.ts.
  - Validate all inputs at runtime (manual checks or zod if installed); reject
    bad values with a clear error the model can recover from.
  - Returns: { decisionId, action, reasonIfNoTrade, trade (if opened), flags,
    accountSummary }.
  - description: "Submit your final trading decision (direction, confidence,
    short rationale) after analyzing the snapshot. Paper trading only. The
    system calculates stop-loss, take-profit and size itself."

5.8 Tool: get_paper_account
  - No parameters. Runs settlement first, then returns: equity, starting equity,
    total return %, open position (with unrealized PnL), last 5 closed trades
    (with R-multiples), win count / loss count, today's realized PnL, whether
    new trades are currently blocked and why.
  - description: "Show the paper trading account, open position and recent
    closed trades. Also checks whether stop-loss or take-profit was hit."

5.9 Tool: reset_paper_account (small, useful for demos and experiments)
  - Resets equity to startingEquityUsd and clears position/history.
    Keep decision log files.

5.10 System prompt  (agent/agent.ts -> SYSTEM_PROMPT)
  Keep the starter's tool-loop mechanics; replace/extend the prompt text with
  (adapt wording, keep the rules):
  ----
  You are Mortis, a Bitcoin paper-trading analyst agent. You analyze live
  BTC/USDT market data and make simulated trading decisions. You never trade
  real money.
  Rules:
  1. Before ANY trading decision, call get_market_snapshot. Never invent or
     guess prices, indicators or account data. If a tool fails, say so.
  2. Read the snapshot top-down: 4h = trend direction, 1h = setup quality,
     15m = entry timing. Prefer trades aligned with the 4h trend. If the
     timeframes conflict or the setup is weak, the correct decision is neutral.
  3. Then call submit_trade_decision with direction (long | short | neutral),
     confidence (0 to 1) and a rationale of at most 3 sentences.
  4. Confidence guide: 0.50 = weak lean, 0.60-0.70 = decent setup, 0.80+ =
     rare and strong, never above 0.95, never 1. Not trading is fine and
     expected most of the time.
  5. Never calculate stop-loss, take-profit or position size yourself; the
     system computes them. Report the numbers the tool returns.
  6. Be honest: this is paper trading, not financial advice, and you cannot
     predict the market. Never claim guaranteed or likely profit.
  7. Keep answers concise: decision, confidence, 2-3 reasons, and the plan
     (entry / SL / TP / size) if a trade was opened.
  8. For wallet, weather or dice requests, use the existing tools as before.
  ----
  Store promptVersion in config and bump it whenever the prompt changes
  (needed for the experiments log).
